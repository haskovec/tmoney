⏺ That confirms it. With -p 1 (one package at a time), all tests pass in ~9 seconds.

  The problem: go test ./... by default compiles and runs multiple test packages in parallel. Multiple packages (db, repository,
  service, integration, cmd) all load the go-duckdb CGO library, which uses DuckDB's native C++ code. On Apple Silicon, when
  multiple processes load and initialize DuckDB simultaneously, it can deadlock.

  This doesn't happen on Intel because the DuckDB native library handles concurrency differently on x86_64 vs arm64.

  The fix: Add -p 1 to the test command in the Makefile.
