 Task 044: Split Transaction Dialog

 Context

 Task 043 (transaction entry dialog) is complete. The next item is 044 - Split transaction dialog, which enables users to split a
 transaction across multiple categories. The spec shows a two-phase approach: a checkbox in the transaction dialog, then a separate split
 editor dialog.

 Approach: Two-Phase Dialog Flow

 1. Add a "Split transaction" checkbox (field index 6) to the existing transaction entry dialog
 2. When checked and saved, open a custom split editor dialog instead of saving directly
 3. The split editor allows adding/removing split rows, each with category, amount, and memo
 4. On Save, create the transaction with splits via CreateWithSplits()

 The split editor is a custom component (not the generic Dialog) because it needs dynamic rows.

 Files to Modify

 - internal/tui/transaction_dialog.go - Add checkbox, modify submit to handle splits
 - internal/tui/app.go - Add split dialog state, message handling, key routing, overlay rendering
 - internal/tui/transaction_dialog_test.go - Update tests for 7-field dialog (was 6)

 Files to Create

 - internal/tui/split_dialog.go - SplitDialog component + App handler methods
 - internal/tui/split_dialog_test.go - Tests

 Implementation Steps

 In buildTransactionDialog(), add after the Status radio field:
 d.AddCheckboxField("Split transaction", false)

 Update submitTransactionDialog():
 - Change guard from len(fields) < 6 to len(fields) < 7
 - When fields[6].Checked is true: parse amount, store pending data, open split dialog
 - When unchecked: existing save flow (unchanged)

 Save category data before calling closeTransactionDialog() since that nils txnDialogData.

 Step 2: Create SplitDialog component (split_dialog.go)

 Data structures:
 type splitRow struct {
     categoryIndex int
     amountField   Field  // reuse Field struct for cursor/editing
     memoField     Field  // reuse Field struct for cursor/editing
 }

 type SplitDialog struct {
     visible     bool
     width       int
     totalAmount models.Money
     rows        []splitRow
     focus       splitDialogFocus  // rows/addBtn/cancelBtn/saveBtn
     rowIndex    int
     fieldFocus  splitFieldFocus   // category/amount/memo within row
     categoryOptions []string
     categoryIDs     []models.ID
     errorMsg    string
 }

 type pendingSplitTransaction struct {
     date      models.Date
     payeeName string
     amount    models.Money
     memo      string
     status    models.TransactionStatus
 }

 Key methods:
 - NewSplitDialog(amount, catOptions, catIDs) - constructor, starts with 1 empty row
 - remaining() - calculates total - sum of entered amounts
 - HandleKey(msg) - routes Esc/Tab/Enter/field-specific keys, returns DialogAction
 - addRow() / removeRow(index) - dynamic row management
 - validate() - checks categories, amounts, sum matches total
 - buildSplits() - produces []*models.Split from row data
 - Render(styles) - renders the full dialog with header, rows, buttons
 - focusNext() / focusPrev() - cycles through: row fields -> [+ Add split] -> [Cancel] -> [Save]

 Focus order: For each row: category -> amount -> memo, then [+ Add split], [Cancel], [Save], wrap.

 Keyboard:
 - Tab/Shift-Tab: navigate focus
 - Esc: cancel
 - Enter: submit (on Save), cancel (on Cancel), add row (on Add), advance (on row field)
 - Up/Down on category: cycle options
 - Text editing on amount/memo: same as FieldText (runes, backspace, arrows)
 - Ctrl+D: remove current row (if >1 row)

 Rendering layout:
 SPLIT TRANSACTION                          [x]

 ──────────────────────────────────────────────

 Category              Amount        Memo

 Household > Cleaning   $30.00       Cleaning supplies
 [+ Add split]

 ──────────────────────────────────────────────
        [Cancel]                    [Save]
